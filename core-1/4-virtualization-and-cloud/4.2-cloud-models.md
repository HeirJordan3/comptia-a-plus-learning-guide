# Cloud Models

CompTIA A+ Core 1 — 220-1201  
Objective 4.2 — Cloud Computing

## What You Need to Know

By the end of this lesson, you should understand:

- What cloud computing offers beyond “a server somewhere else”
- Public cloud vs private cloud
- Hybrid use of both
- Shared / community-style cloud setups for smaller organizations
- Infrastructure as a Service (IaaS / HaaS)
- Software as a Service (SaaS)
- Platform as a Service (PaaS)
- Who manages what in each model

## What Is It?

Cloud computing lets organizations host applications and services outside a traditional local-only data center workflow.

Instead of buying, racking, and building every server by hand, teams can deploy resources quickly, often with a button press, and remove them when demand drops.

Cloud is about:

- On-demand capacity
- Geographic flexibility
- Efficiency
- Financial control over time

## Why Does It Matter?

Help desk and IT support technicians see cloud models when users ask about:

- Microsoft 365 or Gmail-style apps
- Company servers hosted by a cloud provider
- Developer platforms used to build custom apps
- Whether company data lives in a private or public cloud

Knowing IaaS, SaaS, and PaaS helps you understand who is responsible for updates, security, and troubleshooting.

## Real-World Analogy

Think of getting around town:

- IaaS = renting a car — you get the vehicle, but you drive and maintain the trip
- PaaS = renting a chassis with tools already attached — you still build the route and cargo setup
- SaaS = taking a rideshare — you just get in and go; someone else handles the vehicle

## How It Works

### Cloud Advantages

Compared with old physical data center workflows, cloud often lets you:

- Deploy an app instance quickly
- Use as much or as little capacity as you need
- Place services closer to users geographically
- Turn resources off when seasonal demand ends
- Avoid large upfront hardware purchases

In older setups, you might wait for servers to be purchased, delivered, racked, installed, and networked before an app was ready. Cloud compresses that process into moments.

### Public Cloud

A **public cloud** is provided by companies such as:

- Microsoft
- Amazon
- Rackspace and similar providers

You can access it over the internet. Many organizations use public cloud for apps that need broad deployment and internet access.

### Private Cloud

A **private cloud** runs in your own private data center.

You buy and maintain the equipment, then use cloud-style deployment features while keeping control inside your organization.

### Using Both

Many organizations use both:

- Private cloud for internal or sensitive apps
- Public cloud for broader deployment and internet-facing services

### Shared Cloud Among Partners

Some smaller organizations partner to share a cloud they build together.

That gives cloud benefits without one organization carrying the full upfront cost alone.

### IaaS — Infrastructure as a Service

**IaaS** is also sometimes called **HaaS**, Hardware as a Service.

Think of it as renting hardware time in the cloud.

The provider typically gives you:

- CPU
- Storage
- Underlying hardware access

You typically remain responsible for:

- Installing and updating the OS
- Maintaining applications
- Securing the software stack
- Managing your data

Example idea: a website hosted on rented cloud servers where the customer still manages the OS, apps, and data.

IaaS gives more control, but also more management work.

### SaaS — Software as a Service

**SaaS** is on-demand software.

You usually:

- Log in with a username and password
- Use a web-based application

You usually do not manage:

- OS updates
- Application code
- Underlying data center details

The provider handles those layers.

Examples:

- Google Mail / Gmail
- Microsoft 365

SaaS is useful when you want the app ready to use without building it yourself.

### PaaS — Platform as a Service

**PaaS** sits between IaaS and SaaS.

With PaaS:

- You do not maintain the OS or your own full data center
- You still build the application
- The provider gives you the platform and building blocks to run it

Think of arranging modules or building blocks into an app that fits your needs.

Example: Salesforce is often known as SaaS for ready-to-use CRM tools, but it also offers a development platform that works as PaaS.

### Responsibility Matrix

Cloud providers often publish a responsibility matrix so customers know who manages what.

| Model | Customer usually handles | Provider usually handles |
| --- | --- | --- |
| On-premises / fully self-managed | Almost everything: data, apps, OS, network, hardware | Little or none |
| SaaS | Identity/accounts, end-user devices, some access settings | Data center through the application |
| PaaS | Application development and configuration | Platform, OS layer, underlying infrastructure |
| IaaS | OS, apps, data, and most software management | Data center, network connectivity, hardware/CPU/storage |

Exact responsibilities vary by provider and service, but this matrix is the exam-friendly way to compare them.

## Common Mix-Ups

### Public vs Private Cloud

- Public = third-party shared provider access
- Private = your own controlled cloud infrastructure

### IaaS vs SaaS

- IaaS = more control, more management
- SaaS = least management, ready-made app

### PaaS vs SaaS

- SaaS = use the finished application
- PaaS = build the application on a managed platform

### IaaS vs PaaS

- IaaS = you manage the OS and above
- PaaS = provider manages the platform; you focus on the app
