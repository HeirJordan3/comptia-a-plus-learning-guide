## What Is It?

**Virtualization** lets you run multiple operating systems on the same physical computer at the same time.

Each virtualized operating system can have its own:

- Operating system environment
- Virtual CPU resources
- Dedicated memory allocation
- Separate network connection

A virtualized operating system is commonly called a **VM**, or Virtual Machine.

## Why Does It Matter?

Help desk and IT support teams see virtualization when:

- A user needs an older OS for one application
- Developers need a safe test environment
- One physical machine must run Windows, Linux, and macOS tools
- A bad test setup should not damage the main computer

Virtualization is also useful because it is not new. The same basic idea has been used since IBM mainframes in 1967.

## Real-World Analogy

Think of one apartment building with several apartments.

The building is the physical computer. Each apartment is a separate OS environment. People in one apartment can live their own daily life without taking over the whole building. If one apartment has a problem, the others can keep working.

## How It Works

### Multiple Operating Systems on One Device

With virtualization, one physical computer can run several operating systems at once.

Example:

- Host computer running macOS
- A Windows 11 VM
- A Linux VM

All can run at the same time on the same hardware.

### Host-Based Virtualization

If the VMs are running on your desktop OS, that is often called **host-based virtualization**.

Example:

- Primary OS = macOS
- Virtualized OSes = Windows and Linux running on top of it

### Enterprise Virtualization

In enterprise environments, one physical server may run many VMs.

There may be no normal desktop to choose from. Instead, one powerful machine hosts multiple virtual machines for users or services.

### Sandboxing

**Sandboxing** means using an isolated environment for testing.

Developers often create a VM sandbox to:

- Try new code
- Test behavior in different operating systems
- Avoid damaging the main system if something fails

If a problem happens inside the sandbox VM, only that VM is affected.

### Snapshots

Most virtualization platforms support **snapshots**.

A snapshot saves the VM configuration and state at a moment in time.

Typical workflow:

1. Create a snapshot
2. Make changes or run a test
3. If something breaks, revert to the snapshot quickly

This makes testing safer and faster.

### Development and Pre-Production Testing

Virtualization helps developers:

- Write and test code in protected VMs
- Run the same app across multiple OS environments
- Move tested code into a VM that mirrors production

That production-like test VM helps catch problems before end users see them.

### Legacy Software Use

Sometimes virtualization is used because an application only works on an older OS.

Example:

- Main desktop runs Windows 11
- Needed app only runs on Windows 10

Solution: run Windows 10 in a VM while keeping Windows 11 available. Switch between them without rebooting the physical computer.

### Cross-Platform Virtualization

Cross-platform virtualization means running different OS families on the same physical system.

Example on one Mac:

- Native macOS apps
- A Windows VM
- A Linux VM

You can start only the VM you need, run the app, and shut the VM down when finished.

Benefits:

- No reboot just to change OS
- No need for a second physical computer
- Better use of one machine’s resources

## Common Mix-Ups

### Virtual Machine vs Physical Computer

- Physical computer = real hardware
- VM = software-based OS environment running on that hardware

### Sandbox vs Production

- Sandbox = safe testing space
- Production = real environment used by end users

### Snapshot vs Backup of the Whole Host

A snapshot usually restores a VM quickly. It is not the same idea as a full backup of the entire physical computer.

### Host OS vs Guest OS

- Host = the main OS on the physical machine
- Guest = the OS running inside the VM
