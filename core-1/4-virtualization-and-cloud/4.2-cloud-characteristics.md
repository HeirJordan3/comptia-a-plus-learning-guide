# Cloud Characteristics

CompTIA A+ Core 1 — 220-1201  
Objective 4.2 — Cloud Computing

## What You Need to Know

By the end of this lesson, you should understand:

- Internal / private cloud vs external / public cloud
- Metered vs nonmetered cloud usage
- Ingress and egress traffic costs
- Elasticity
- Availability and redundancy
- File synchronization across locations
- Multitenancy

## What Is It?

Cloud infrastructures can operate in different ways depending on ownership, billing, and shared use.

This lesson focuses on common cloud characteristics:

- Who owns and runs the cloud
- How usage is billed
- How capacity scales
- How uptime is maintained
- How data stays synchronized
- How many customers share the same infrastructure

## Why Does It Matter?

Help desk and IT support learners see these ideas when:

- A company asks whether to use private or public cloud
- A bill changes because traffic or storage usage changed
- An app scales up during busy times
- Users expect cloud services to stay online
- Files appear across regions or devices
- Multiple companies share the same cloud provider platform

## Real-World Analogy

Think of cloud options like housing:

- Private / internal cloud = owning your own building
- Public / external cloud = renting space in a large shared complex
- Metered billing = paying based on water and electricity used
- Nonmetered billing = flat monthly rent for a set amount of space
- Elasticity = adding or removing rooms as the family grows or shrinks
- Multitenancy = many tenants in the same complex, with locked doors between them

## How It Works

### Internal / Private Cloud

Some organizations build their own **private cloud**, also called an **internal cloud**.

They usually:

- Own the data center
- Buy the equipment and storage
- Install and maintain everything themselves

Those resources are dedicated to that organization only.

Trade-off:

- Higher upfront cost to buy and set up equipment
- Once built, there are usually no ongoing pay-as-you-go cloud meter charges for using your own capacity

### External / Public Cloud

Other organizations prefer not to own equipment or run a data center.

They use an **external cloud**, commonly called a **public cloud**.

Examples of public cloud providers include:

- Amazon
- Microsoft
- Rackspace and similar providers

In a public cloud:

- Many customers share the same underlying resources
- One customer should not see another customer’s data
- Customers may still share the same storage systems, CPUs, and networks at the infrastructure level

Public cloud usually has little or no large equipment purchase up front, but you still pay for what you use.

### Metered Utilization

**Metered utilization** means you pay based on how much you use.

Possible metered costs include:

- Storage used
- Ingress traffic — data coming into the cloud
- Egress traffic — data going out of the cloud

Ingress and egress may have different prices.

At the end of the month, the provider adds up usage and sends an invoice. A busy month usually costs more than a quiet month.

### Nonmetered Pricing

On the consumer side, many services use **nonmetered** or fixed pricing.

Example:

- Pay a set monthly price for up to 2 GB of cloud storage
- Upload and download amounts may not change that monthly price
- You are paying for a maximum storage block, not per-byte traffic

Organizations choose private vs public and metered vs nonmetered based on cost and operational needs.

### Elasticity

**Elasticity** is the ability to scale up or scale down as needed.

Examples:

- Add more application instances during busy periods
- Reduce capacity during slower periods
- Often do this quickly, sometimes automatically

Push-button or automatic scaling is one of the biggest advantages of cloud computing. You pay for what you need when you need it.

### Availability

Cloud services are designed for high **availability**.

Providers often use:

- Redundant systems
- Multiple data centers
- Failover when hardware or network problems occur

In extreme cases, a provider may move workloads from one data center to another to keep services online.

### File Synchronization

Cloud systems can make data appear available in many places.

A database or files maintained in one region may be duplicated to other data centers around the world.

Synchronization may be:

- Built into the application and managed by the customer
- Handled automatically by the cloud platform, especially during data center moves

### Multitenancy

**Multitenancy** means many customers, or tenants, share the same cloud infrastructure at the same time.

Providers use technologies and processes to keep customer data and environments separated.

Why it matters:

- Better efficiency for the provider
- Better cost efficiency because resources stay in use
- Customers still expect privacy and isolation from each other

## Common Mix-Ups

### Private vs Public Cloud

- Private = dedicated to one organization
- Public = shared provider platform used by many customers

### Metered vs Nonmetered

- Metered = usage-based bill
- Nonmetered = fixed price for allocated resources

### Ingress vs Egress

- Ingress = in
- Egress = out

### Elasticity vs Availability

- Elasticity = changing capacity with demand
- Availability = staying up and reachable

### Multitenancy vs Lack of Security

Multitenancy means shared infrastructure, not shared private data. Providers are expected to keep tenants separated.
