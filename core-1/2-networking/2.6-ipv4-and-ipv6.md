# IPv4 and IPv6

CompTIA A+ Core 1 — 220-1201  
Objective 2.6 — IP Addressing

## What You Need to Know

By the end of this lesson, you should understand:

- What an IPv4 address looks like
- That IPv4 is a 32-bit address made of four octets
- Why public IP addresses must be unique on the internet
- Why private addressing and NAT exist
- The RFC 1918 private IPv4 ranges
- What an IPv6 address looks like
- That IPv6 is a 128-bit address written in hexadecimal
- Why DNS matters even more with IPv6
- The common IPv6 /64 network and host split

## What Is It?

**IP** stands for Internet Protocol.

IPv4 is still one of the most widely used addressing systems on networks. IPv6 is the newer version designed to solve IPv4’s address shortage.

Both versions move traffic across networks, but they look different and are configured differently.

## Why Does It Matter?

Help desk technicians constantly work with IP addressing when:

- A device cannot reach the internet
- A home router uses a 192.168.x.x address
- A company uses 10.x.x.x internally
- A system shows a long hexadecimal IPv6 address
- DNS is needed because nobody wants to memorize IPv6 addresses

Understanding IPv4 and IPv6 helps you recognize normal addresses and explain public vs private communication.

## Real-World Analogy

Think of IPv4 like a city with a limited number of street addresses.

When the city ran out of unique public addresses, neighborhoods started using internal apartment numbers (private addresses) and one front desk phone number (NAT) to talk to the outside world.

IPv6 is like redesigning the city with so many addresses that every person could have a huge number of unique ones.

## How It Works

### IPv4 Address Structure

IPv4 is a **32-bit** address.

Humans usually write it as four decimal numbers separated by periods:

```text
192.168.1.131
```

Each of those four numbers is an **octet**.

| Term | Meaning |
| --- | --- |
| Bit | A single 1 or 0 |
| Octet | 8 bits |
| Byte | Another way to say 8 bits |
| IPv4 address | 4 octets = 32 bits = 4 bytes |

Each octet can be a number from **0 to 255**. No IPv4 octet goes above 255.

### Public IPv4 Addresses

On the public internet, devices need unique IP addresses to communicate.

Example idea:

- One device might use `1.1.1.1`
- Another might use `2.2.2.2`

There are about **4.29 billion** possible IPv4 addresses.

That is not enough for the many billions of internet-connected devices in use today.

### Private Addresses and NAT

To stretch IPv4, networks use **private addresses** and **NAT**.

NAT stands for Network Address Translation.

Typical design:

- Inside a company or home: many devices use private IPs
- Outside to the internet: traffic can share one or a small number of public IPs through NAT

Private addresses let devices talk to each other internally. NAT helps them communicate outward without using a unique public IPv4 address for every internal device.

### RFC 1918 Private Ranges

Private IPv4 ranges are defined in **RFC 1918**.

RFC stands for Request for Comments. In this case, it is the worldwide standard for these private ranges.

| Private Range | Approx. Size | Common Use |
| --- | --- | --- |
| `10.0.0.0` – `10.255.255.255` | Over 16 million addresses | Large corporate networks |
| `172.16.0.0` – `172.31.255.255` | Just over 1 million addresses | Medium private networks |
| `192.168.0.0` – `192.168.255.255` | Just over 65,000 addresses | Home networks |

If you have seen `192.168.1.1` on a home router, that is the third private range.

### IPv6 Address Structure

IPv6 was designed with a much larger address space.

| Version | Length | Approx. Address Space |
| --- | --- | --- |
| IPv4 | 32 bits | About 4.29 billion |
| IPv6 | 128 bits | About 340 undecillion |

IPv6 is written in **hexadecimal**, not decimal, and uses colons to separate sections.

Example compressed form may use double colons. The full form of one example looks like:

```text
fe80:0000:0000:0000:5d18:0652:cffd:8f52
```

Each IPv6 group is **16 bits** (2 octets). The full address is **128 bits**, or **16 bytes**.

### Why DNS Matters Even More with IPv6

IPv6 addresses are long and hard to memorize.

Because of that, **DNS** becomes especially important. Users and admins rely on names instead of typing full IPv6 addresses.

### IPv6 Network and Host Split

IPv6 usually does not require the same kind of tight subnetting common with IPv4.

A common design:

- First **64 bits** = network prefix
- Last **64 bits** = host ID

That means the default subnet size people often think about with IPv6 is **/64**.

```text
[ network prefix - 64 bits ][ host ID - 64 bits ]
```

## Common Mix-Ups

### Public vs Private IPv4

- Public = unique on the internet
- Private = used internally; needs NAT to reach the public internet in typical designs

### IPv4 vs IPv6 Appearance

- IPv4 = decimal with dots
- IPv6 = hexadecimal with colons

### Octet vs IPv6 Group

- IPv4 octet = 8 bits
- IPv6 group = 16 bits

### NAT vs More Public Addresses

NAT helps conserve IPv4 addresses. IPv6 expands the address space so scarcity is no longer the same problem.
