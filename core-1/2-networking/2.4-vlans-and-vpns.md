# VLANs and VPNs

CompTIA A+ Core 1 — 220-1201  
Objective 2.4 — Network Configurations

## What You Need to Know

By the end of this lesson, you should understand:

- What a LAN and a broadcast domain are
- Why separate physical switches create separate broadcast domains
- What a VLAN is and why it is useful
- How VLANs provide logical segmentation on one switch
- Why devices on different VLANs cannot communicate without a router
- What a VPN is and why encryption matters
- What a VPN concentrator does
- Client-to-site VPNs
- Always-on VPNs
- Site-to-site VPNs

## What Is It?

Networks often need **protection** and **segmentation**.

Two technologies that help with that are:

- VLAN — Virtual Local Area Network
- VPN — Virtual Private Network

A short comparison:

- VLANs separate devices into different broadcast domains
- VPNs protect communication by encrypting data across a network

## Why Does It Matter?

Help desk and IT support technicians see VLAN and VPN topics in real work:

- Users on one department network should not freely reach another
- A company wants better security and organization without buying more switches
- A remote worker needs a secure connection into the company network
- Two office locations need to share data safely over the internet

Understanding these ideas helps you explain connectivity, security, and remote access problems more clearly.

## Real-World Analogy

### VLAN Analogy

Think of one apartment building with locked floors.

Everyone is in the same physical building, but Floor 1, Floor 2, and Floor 3 are separated. People on Floor 1 do not automatically hear announcements meant for Floor 3.

A VLAN works like that on a switch. Devices share one physical switch, but they are separated into different logical networks.

### VPN Analogy

Think of sending a sealed envelope through the public mail.

Anyone can see that a package is traveling, but they cannot read what is inside.

A VPN encrypts the data so it can travel across a public network, such as the internet, without being readable if someone intercepts it.

## How It Works

### Start With a LAN

A LAN is a Local Area Network.

In simple terms, a LAN is a group of devices connected together into a single **broadcast domain**.

That means:

- If one device sends a broadcast
- The other devices in that same LAN also see it

### Separate Switches Mean Separate Broadcast Domains

If you have two physical switches, you usually have two separate broadcast domains.

```text
Red network switch          Blue network switch
[Device A] [Device B]       [Device C] [Device D]

Broadcast on red  → seen only on red
Broadcast on blue → seen only on blue
```

From a security and organization perspective, that design can be good.

But it may waste switch ports, power, and rack space. For example, two 24-port switches might each have only a couple of devices connected.

### VLANs Solve That Problem

A VLAN, or Virtual Local Area Network, lets you assign different interfaces on one switch to different VLANs.

That means you can put many devices on one physical switch while still keeping them in separate broadcast domains.

```text
                 One Physical Switch
 ------------------------------------------------
 | Red VLAN ports | Blue VLAN ports |
 | Device A       | Device C        |
 | Device B       | Device D        |
 ------------------------------------------------

Broadcast on red VLAN  → seen only by red VLAN devices
Broadcast on blue VLAN → seen only by blue VLAN devices
```

Now you have:

- One switch
- One power source
- One rack space
- Multiple VLANs with logical separation

### Example VLAN Layout

A switch might be configured with several VLANs, such as:

| VLAN | Area |
| --- | --- |
| VLAN 1 | Gate room |
| VLAN 2 | Dining room |
| VLAN 3 | Infirmary |

Devices on one VLAN are not able to communicate with devices on another VLAN by default, because they are in completely separate broadcast domains.

### Communicating Between VLANs

If different VLANs need to talk to each other, you need a **router**.

Options include:

- An external router
- A switch that supports routing functionality

Remember:

- VLANs separate traffic
- Routing is required to allow communication between VLANs

### What Is a VPN?

A VPN, or Virtual Private Network, lets devices communicate across a network while encrypting the data being sent.

If someone captures that traffic with a packet capture tool, they should not be able to understand the contents.

### VPN Concentrator

A **concentrator** is a specialized device that encrypts and decrypts VPN traffic in real time.

It often:

- Accepts encrypted connections from remote users or sites
- Decrypts the traffic for the internal network
- Encrypts replies before sending them back out

A concentrator may be:

- Built into a firewall
- A purpose-built appliance
- A software solution running on a server

Many operating systems include VPN client software. Organizations may also use third-party VPN software.

### Client-to-Site VPN

If you have worked from home, you have probably used a **client-to-site VPN**.

- Client = the remote user
- Site = the concentrator at the edge of the corporate network

```text
Remote user (home)
        |
   Encrypted tunnel
        |
  VPN concentrator
        |
 Corporate network
```

All communication from the remote user to the concentrator is encrypted.

The concentrator decrypts the traffic and forwards it to internal resources.

### Always-On VPN

Some client-to-site VPNs are configured as **always-on**.

That means the VPN connection starts automatically when the user turns on and logs into the laptop.

The user does not have to manually launch VPN software. If the device is online, it already has an encrypted channel back to the concentrator.

### Site-to-Site VPN

Large organizations often need to connect remote offices to a central corporate network.

A **site-to-site VPN** creates an encrypted connection between two sites, usually over the internet.

This is commonly implemented with firewalls:

```text
Corporate network --- Firewall === Encrypted VPN === Firewall --- Remote site
                               (over the internet)
```

Inside each site, traffic may be in the clear. Across the internet, traffic is encrypted by the site-to-site VPN.

In this design, the firewalls often act as the VPN concentrators.

## Common Mix-Ups

### VLAN vs VPN

- VLAN = separates networks / broadcast domains
- VPN = encrypts communication across a network

### Separate Switch vs VLAN

- Separate physical switches can create separate broadcast domains
- VLANs create separate broadcast domains on one physical switch

### Client-to-Site vs Site-to-Site

- Client-to-site = one remote user to company network
- Site-to-site = one office/network site to another office/network site

### VLAN Separation vs Routing

- Being on different VLANs does not allow normal communication by itself
- A router is needed for communication between VLANs
